Slaloop support and user guide

Contact: support@studiowebworks.com. We answer within two working days (Central European Time).

Getting started

  1. A Jira administrator opens Apps → Manage your apps → Slaloop SLA policies and presses New policy.
  2. Give it a name and a JQL scope, such as project = HELP.
  3. Choose the statuses that pause and stop the clock, the goals and the working hours, then save.

Clocks start at once. Open work items get theirs from their history; the policies page shows the count as it runs.

How the clock works

  • Start: when the work item is created, or when it first enters a start status if you chose any.
  • Pause: while it is in a pause status. Paused time does not count.
  • Stop: when it enters a stop status. The SLA is then Met or Missed.
  • Reopen: if a stopped work item moves back, the same clock carries on with the time it had.
  • Working hours: only time inside the policy's hours counts. Outside them the timer stands still.
  • Priority: the current priority sets the goal. If the priority changes, the new goal applies to the time already used, so raising a priority can cause a breach at once.
  • A breach stays a breach, even if the priority is lowered later.
  • If a work item leaves the scope before it finishes, its clock is removed. A finished result stays.

Statuses you will see

On track, At risk (inside the warning time), Paused, Waiting (not started), Breached (late and still open), Met and Missed (finished). A work item with several SLAs shows the most urgent in its fields, and all of them in the SLA panel.

Rules

A rule runs before the breach (at the warning time) or on the breach. It can add a comment with a mention, set the priority, assign the work item, or move it to a status. Rules run on a five-minute check, so one can run up to about five minutes after the moment.

  • Each rule runs once per work item.
  • If the warning and the breach land in the same check, only the breach rules run. Give the warning at least ten minutes before the goal to be sure it runs on its own.
  • A priority whose goal is not longer than the warning time gets no warning, only the breach.
  • Rules run as the app, so the Slaloop app user needs the permission in the project's permission scheme.
  • To move a work item, the workflow must have a transition from its current status to the one you chose, and that transition must not need a screen.
  • Rules do not run for breaches from before the policy was saved, or for a work item that enters the scope more than 15 minutes after its breach.
  • Rules do not run on a work item that is already stopped or paused.

If a rule fails, the reason shows on the policies page and in the work item's SLA panel. Fix the cause. The rule does not run again by itself on that work item.

Queues and JQL

Slaloop keeps two Jira fields up to date, within five minutes:

  • "SLA status" = Breached finds late work. Use the status names above, with =, not ~.
  • ORDER BY "SLA due" ASC sorts a queue by what is due first.

To see them on a board or a work item, add the fields as you would any other field.

Report and gadget

Apps → SLA report shows met, missed and open per policy, and the work items behind them. Export CSV gives the same rows. Both hold the 1,000 most urgent rows and say so when there are more; choose a shorter period for the rest. Everyone sees only the projects and work items they can see in Jira. The counts per policy go by project, so they can include a work item hidden by an issue security level; its row is not shown. Add the SLA overview gadget to a dashboard for the summary.

Changing a policy

Saving a policy restarts its open clocks from each work item's history, with the new settings. Finished results keep the result they had. Deleting a policy deletes its clocks and results; turning it off keeps the results.

If a policy's JQL stops working, for example when a field is deleted, the policies page says so and its clocks wait. When Jira accepts the JQL again, Slaloop reads those work items again by itself.

Slaloop stores status ids. If you add a project with its own statuses later, open the policy and save it again so the new statuses are included.

How long results are kept

Results stay for 400 days after a work item stopped, past the 365 days the report can show, then Slaloop removes them. Export a CSV if you need them longer.

Licence

If the licence lapses, clocks stop updating and rules stop running. They catch up from history when it is back.
