Versionloop support and user guide

Contact: support@studiowebworks.com. We answer within two working days (Central European Time).

What it does

A sync group is one lead project and the projects that follow it. Versionloop copies the lead's versions, components or both to every follower, and keeps the copies in step from then on. The lead always wins.

  • Versions: name, description, start date, release date, released and archived.
  • Components: name, description, component lead and default assignee.

Company-managed and team-managed projects both work. The order of versions is not synced.

Getting started

  1. A Jira administrator opens Settings → Apps, then Versionloop under Apps in the sidebar.
  2. Press New group. Give it a name, choose the lead project and the followers, and choose versions, components or both.
  3. Press Save and preview. Nothing changes yet: the preview lists, per follower, what would be created, updated, linked or left alone.
  4. Press Apply. The group is now Live.

How it syncs

  • Live: a change in the lead reaches the followers within seconds, or a few minutes when many changes come at once.
  • Nightly check: once a day Versionloop compares every live group and repairs anything that drifted, such as a copy someone edited or deleted by hand in a follower. Check now runs the same check at once.
  • Same name: if a follower already has an item with the same name (not case sensitive), Versionloop links it instead of making a second one. The preview names these items.
  • Renames follow the link, so a renamed version stays the same version in every follower.
  • Items only in a follower are never touched. Versionloop only changes copies it made or linked.

Name filter

To sync only some items, give patterns separated by commas, where * matches anything: 2026.*, Release *. The filter applies to versions and components alike, so use separate groups if they need different filters. An item that leaves the filter keeps its copies, which are no longer synced.

Deletes

Off by default. When the lead deletes an item, the copies stay in the followers and are no longer synced.

When you turn deletes on:

  • Only items Versionloop linked are deleted, including same-name items it adopted.
  • For versions, work items move to the version chosen in the lead project when it was deleted (fix and affects versions each to their own), else to the version named in the group. A merge in the lead moves them to the merged copy.
  • For components, Jira does not tell apps where work items went, so they move to the component named in the group.
  • With neither, a copy that work items still use stays, and is no longer synced.
  • If the lead project itself is deleted or cannot be read, nothing is deleted in the followers.

Changing a group

Changing the projects, what syncs, the filter or the delete settings turns the group off until you apply a new preview, so what runs is always what you saw. Renaming the group does not. Pause stops a group; Review and apply starts it again. Deleting a group stops syncing and leaves every version and component where it is.

A project can follow one lead for versions and one for components. A follower cannot lead another group, because Jira does not tell apps about their own changes, so a chain would not pass changes on.

Problems

When an item cannot be synced, the groups page shows Problems with the project, the item and Jira's reason, such as a name the follower already uses for another item. Fix the cause; the next live change or nightly check tries again. A follower that has been deleted or moved to the trash is reported the same way.

Audit log

Every change Versionloop makes is in the Audit log tab: when, which group and project, the item, the old and new values, how it happened (live, nightly check, apply, check now) and who changed the lead. Rows are kept for 365 days.

Limits

  • 50 groups per site, 50 followers per group.
  • Components managed in Compass are not synced; such a project shows a problem for components.
  • Only Jira administrators can see the Versionloop page.

Licence

If the licence lapses, syncing stops. When it is back, the nightly check (or Check now) brings every follower up to date.
